# 生产线候选的扩展窗口滚动回测（2018-2025）

本目录把 `src/` 的生产线候选（`core_satellite`：20% 十年国债 + 10% 黄金底仓 + 65% 权益卫星 topk=6）放到比生产协议更长的窗口上重跑，用于和沪深300、标普500、全国社保基金做同窗口对比。模型逐年按时间先后训练与测试，但策略规则和候选选择已受已查看历史影响；2018—2025不是策略层面的独立盲测。

## 为什么起点是 2018，而不是 2016

- 行情数据自 **2016-01-04** 起（`data/market.duckdb` 的 `bars_raw`）
- walk-forward 每个测试年需要「测试年前一年作验证集 + 更早样本作训练集」（`src/models.py:62-64`），且训练样本 < 200 或验证样本 < 50 时**直接抛错**（`src/models.py:68`）
- 实测把各年当测试年时的样本量：

| 测试年 | 训练样本（需 ≥200） | 验证样本（需 ≥50） | 结果 |
|---|---|---|---|
| 2016 | **0** | **0** | 抛错 |
| 2017 | **0** | 515 | 抛错 |
| **2018** | **515** | 1128 | **最早可行** |
| 2019 | 1748 | 1467 | OK |
| 2020 | 3354 | 2030 | OK |

**2016/2017 无法对任何需要训练的模型做样本外测试**——那两年在这套设计里只能是训练/验证期。2018 折训练样本仅 515 行，模型质量弱于后续折，已在 `protocol.json` 的 `early_fold_note` 与产物中标注。要覆盖 2016 起，必须补 2014 年之前的行情并重建资格池及历史标的目录。

### 2018 折为什么只有 515 行：不是没抓数据，是标的当时才上市 + 规模数据只有季报

行情从 2016-01-04 就抓了（`meta.list_date` 31/31 完整，最早 2005-02-23），稀疏来自三层：

1. **ETF 陆续上市**：2016 年初只有 11 只，2017 年底 19 只，2020 年底才凑齐 31 只。
2. **规模数据（`net_asset`）只有季报**：`nav` 表 66226 行里仅 1138 行（1.7%）带 `net_asset`，最早 `nav_date` 2016-03-31、`ann_date` 2016-04-20。`src/universe_filter.py:37` 会丢掉无 `net_asset` 的行，而"缺规模不放行"，**因此 2016-04-21 之前没有任何 ETF 合格**。这一条是 2016 年样本最少的直接原因。
3. **250 交易日上市观察期**对新上市标的是硬约束（如 512880 上市 2016-08-08 → 首次合格 2017-11-22）；但对上市早于数据起点 730 天的 11 只老 ETF，`src/universe_filter.py:31-32` 有豁免，故不是它们的瓶颈。

实测各年末合格标的数：**2016 → 5 只、2017 → 7 只、2018 → 8 只、2019 → 12 只、2020 → 20 只、2021 → 28 只**。

另外两只从未合格：`SH513100` 纳指、`SZ159920` 恒生，因 `EXCLUDE_QDII=True` 被永久排除（`src/universe_filter.py:51-52`）。`SH510880` 红利（2020-01-14）、`SZ159928` 消费（2019-05-20）、`SH512010` 医药（2019-03-07）则因流动性/规模门槛长期不达标，与上市时间无关。

## 与生产协议的关系

- 使用**本目录自己的** `protocol.json`（`research_start` 前移到 2018-01-01），其余候选、模型、执行与风险参数与 `research_protocol.json` 逐项一致
- **不改写** `research_protocol.json`，**不调用** `src.runs.publish`，因此不切换 `output/current_run.json`
- 产物只写入 `output/prod_candidate/runs/<run_id>/`；`manifest.json` 与 `results.json` 都记录 `production_pointer_unchanged: true`，并记录本目录协议与生产协议的 SHA256
- 执行引擎完全复用 `src.market` / `src.models` / `src.simulation`，与研究线口径一致

## 运行

```powershell
.venv\Scripts\python.exe -m research.prod_candidate.run
```

产物在 `output/prod_candidate/runs/<run_id>/`：

- `results.json` — 各模型指标、逐年收益、协议哈希、`production_pointer_unchanged`
- `folds.json` — 每折的 train/valid 样本量与标签截止日
- `manifest.json` — 引擎文件哈希、数据截止日、交易标的
- `report_<model>.csv` / `trades_<model>.csv` / `predictions_<model>.pkl`
- `research_source/` — 本目录源码副本（冻结溯源）

若 `data/market.duckdb` 的末日与协议 `research_end` 不一致，运行会拒绝执行，需先更新协议。

## 实测（2018-01 ~ 2026-09，9 折）

| 模型 | 累计 | 年化 | 最大回撤 |
|---|---|---|---|
| **lightgbm（主）** | 96.39% | 8.08% | −19.27% |
| momentum | 57.32% | 5.35% | −25.70% |
| ridge | 27.32% | 2.82% | −24.89% |

2018-2025 完整自然年（lightgbm）：年化 **9.09%**、累计 100.59%、最差完整年度 **−15.01%（2018）**、年度粒度回撤 −4.09%。

## 关键结论

扩展到 2018 后，生产候选的最差完整年度为 **−15.01%（2018）**，**不满足**「最差年度 ≥ −5%」；而在 2021-2025 窗口里该项为 −4.06%（2022），看似达标。**本次较短窗口遗漏了2018年的重要亏损风险**；不能推广为所有短窗口必然高估表现。

按联合目标（CAGR≥13.50% / 最差年≥−5% / 回撤≤40%）判定：生产候选在 2018-2025 上满足 **1/3**，`trend200_vol15` 与标普500全收益（人民币）各满足 2/3。

本目录为研究性回测，不构成投资准入，也不改变正式策略与账户。

2026-09-23的[周频独立核实与归因](../../docs/STRATEGY_AB_AUDIT_20260923.md)进一步发现：2018年LightGBM账户中权益ETF贡献约−15.22个百分点；协议设定的十年国债ETF（511260）当年没有合格交易日，预算保留现金。按每周首交易日收盘决策、次交易日开盘执行，2018—2025共同日历的LightGBM为CAGR 6.28%、最差年−14.90%、最大回撤19.03%，仍未满足当前三项目标。此周频结果沿用已归档的日频训练预测，仅改变决策日程；与A比较时还存在复权全收益代理和现金分红账户的口径差异，不能作严格同账户胜负判定。
