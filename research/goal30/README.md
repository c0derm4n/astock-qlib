## 运行

```powershell
# 原规则哈希验证、95个已有配置的平均回撤筛查、十年现金重建与账本审计
.venv\Scripts\python.exe -m research.goal30.audit --restart
```

新产物位于 `output/goal30`；`latest_audit.json` 指向完整核验，`daily/latest_check.json` 保存最近一次实际检查。每日命令没有历史日期参数；过去日期的测试只能写入独立验证目录，不计作前瞻。

本任务已配置北京时间每天19:00自动检查，自动化ID为`30-etf`，休市日安静跳过；本地文件任务运行时需电脑开机且桌面应用保持运行。首次交易日调度结果须以将来的实际记录核对，不能用周日跳过测试代替。

## 每日输出含义

- `allocation_reference` 为当日资格下的长期权重目标。3个百分点漂移带、风险约束、30%日双边换手、100份整数买入及2%成交额参与率沿用原回测。
- 未提供账户时，`rebalance_needed=null`：不知道用户仓位，不能认定已空仓或需要买入。
- 已核对账户下的 `target_weights` 与 `paper_orders` 为模拟测算。`orders=[]`、`executable=false`：当前规则未通过投资准入，不能把这些结果当作实盘指令或成交。`paper_decision_path` 指向带唯一决策/订单编号的模拟决策，可与账户的逐笔模拟成交回报对账。
- 正式行情过期、必需价格缺失、池外账户持仓或规则哈希改变时停止信号计算。更新失败保留错误，并允许同日修复后重试；有效观察不覆盖。
- `notification_needed` 表示与上一有效观察相比出现目标、资格替代、模拟调仓或阻断项变化。同日重复和休市检查不要求通知。

仍缺历史目录、公司行动来源审计及126日真实前瞻。每日权重文件不等于合格前瞻账户；实际现金、份额和成交回报尚未提供，不虚构执行记录。整个投资目标仍未完成。

## 账户与前瞻观察的操作顺序

1. 使用用户明确核对的账户，19:00运行每日命令并指定 `--account`。程序计算份额，把账户快照和下一交易日模拟订单事前冻结；不会自动初始化或改写用户持仓。
2. 下一交易日按模拟交易平台的真实回报整理成交记录；每笔填写冻结决策中的 `decision_id`、`order_id`，以及唯一 `execution_id`、标的、方向、实际份额、价格、费用和带时区的成交时间。不能把建议数量或参考收盘价直接当作已成交回报。
3. 导入该账户的模拟回报：

```powershell
.venv\Scripts\python.exe -m src.account --account 用户核对的账户.json apply-fills --decision 每日结果中的paper_decision_path --fills 模拟成交回报.json
```

4. 当天19:00的同一每日命令先核对本次开盘执行及收盘净值，再冻结下一交易日信号。只有账户现金/份额可由旧快照和已核对回报重建，且每个订单完成至少95%、成交时间在09:25—09:35内，才计为合格日。无需调仓的日期要求账户无不明变动，不要求虚构成交。
5. 分红、折算等使用已有 `src.account apply-actions` 按核对凭证入账；前瞻模块独立核对新增公司行动的日期、来源、指纹与现金/份额变动。现金注入不能当作策略收益。

`forward_evidence` 报告已记录天数、连续合格天数、失效日期和时效。漏交易日或账户衔接中断会重新累计连续区间；代码/规则或账户路径变化使用独立记录范围。126日且时效合格只代表前瞻这一项通过，不能自动打开整体投资准入。

前瞻产物位于 `output/goal30/forward`。历史补记、替换已冻结信号、覆盖已记录收盘均被拒绝。首次新建观察只能从之后的交易日开始；当前没有用户账户或实际模拟回报，合格天数仍为0。
