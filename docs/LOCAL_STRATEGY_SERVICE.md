# 本地双策略服务 v3.0.1

在项目根目录运行：

```powershell
.\start_local.ps1
```

或双击 `start_local.bat`。浏览器地址 `http://127.0.0.1:8000`，前后端由一个本地进程提供，按 Ctrl+C 停止。端口冲突可用 `.\start_local.ps1 -Port 8001`；已构建后可加 `-SkipBuild`，启动时发现快照过期会自动尝试更新；需要强制更新可加 `-Refresh`。启动浏览器如果先于服务就绪，稍后重新加载即可。

首次安装需 Python 项目 `.venv`、`requirements.txt`、`backend/requirements.txt` 及 Node.js/npm。启动脚本自动执行前端 `npm ci`（缺少 node_modules 时）和构建，不自动修改系统环境。

## 正式口径

- 两条正式服务策略登记在根目录 `strategy_registry.json`：LightGBM 核心卫星与固定通信/黄金 `trend200_vol15`。统一从2016-09-12、各100万元现金账户开始；现金利息0。
- 每周首个中国交易日收盘评估，建议运行时间19:00；下一交易日开盘执行模拟订单。非信号日不产生新单；同一ETF的小额漂移、最小持有期、风险、现金与成交额规则共同决定是否触发。页面刷新按钮是手动更新，不安装自动调度。
- LightGBM每自然年训练一次：前一年验证、更早年份训练，20日标签清除跨界样本；最新建议复用当前年度模型，不改用另一套全样本重训模型。训练/验证不足的年度保留现金，不伪造预测。
- LightGBM沿用复权全收益代理账户，模型数量是复权等值份额；固定策略沿用实际份额、登记权益、除息应收和支付现金账本。两个账户估值口径没有强行混为一种。
- v3.0.1修复复权等值份额产生的无触发碎单：目标权重保持不变时不委托；调仓指令采用整数份额。复权代理完全退出时注销小数等值份额，真实账户委托使用整数零股清仓；新回放与旧冻结图表可能略有差异，不回写旧结论。
- 两条策略均保留佣金万三、最低0.2元、基础滑点5bp及成交额冲击，100份整数买入、2%成交额参与率；信号价是收盘参考价，开盘成交还需检查价格、现金和资格。
- 通信策略的沪深300替代仅在通信市场资格失效时发生。通信跌破200日趋势线时转现金，不自动轮换行业。
- 正式服务登记由本次用户授权；投资准入仍未通过。页面同时检查年化≥13.5%、最差完整自然年≥−5%、最大回撤≤40%，并保留存续标的、公司行动完整审计和真实前瞻不足状态。

## 数据与建议

正式库 `data/formal/market.duckdb` 首次从已完成的2014/15年补数库复制，验证原始哈希。免费增量采用腾讯原价和新浪公司行动，以旧因子锚定、检查历史重叠及交易日覆盖，全部境内标的验证后再原子切换。只用已经公告的历史规模；当前规模不能回填历史。

数据截止日取上海时区19:00前的上一交易日，19:00后允许当日。服务不会用盘中日线生成当日收盘信号。更新失败保留最后有效快照并显示错误。新增公司行动缺少登记日、支付日证据时，现金策略构建失败，禁止默默忽略分红；补充 `strategy_corporate_actions.json` 后重跑。

“最新调仓建议”使用该策略模型账户在最新周度信号收盘时点的现金与持仓。当前模型持仓则按数据截止日估值，两者可能不同。执行窗口已过的建议显示为历史信息；过期数据提示刷新。所有建议只用于模拟，不向券商发单。

“用我的账户试算”要求输入上述信号日收盘的现金、持仓份额和已持有交易日；输入仅在本地请求中使用，不写入账户文件。不会将模型持仓认作用户真实账户。试算绑定所见快照，刷新后需要重算。

“历史持仓”位于最新调仓建议与资金曲线之间，按新到旧展示最近十个自然周（含数据截止周）。取每周最后一个交易日收盘后的模型实际持仓，展示ETF及仓位、账户资金和可用现金，点击“查看明细”可看份额、市值与分红应收。本周未完成时标注截至日期；空仓周保留，整周休市时沿用并标注上一交易日持仓。历史持仓来自回放持仓账本，不用当前持仓或目标配置回填历史。

## 产物与接口

- `output/strategies/runs/<run_id>/` 保存协议、输入哈希、年度模型、预测、完整回放、交易、建议上下文、JSON图表和完成校验。
- 仅所有策略完成并验证周频T+1、现金和成交额后，才原子发布 `output/strategies/current.json`。旧 `output/current_run.json` 与历史冻结实验保持原状。
- `GET /api/strategies` 返回同一运行的两条策略、资金/回撤序列和年度指标。
- `POST /api/strategies/refresh` 启动独立刷新；`GET /api/strategies/refresh/status` 返回状态与日志。
- `POST /api/strategies/{id}/preview` 试算输入账户。写请求要求 `X-Local-Request: 1`，只接受本地页面来源；服务只监听127.0.0.1。
- 导航“开发后台”位于 `/#/development`，总览、选ETF清单、周度调仓、回测分析和数据管道统一使用当前正式双策略快照。旧网页地址自动跳转至对应新页面，原结果文件归档保留。
- 开发后台只调用 `/api/development/*` 和正式 `/api/strategies/*`；原研究接口仅兼容历史脚本，不在新后台页面或API文档中展示。

手动后台构建：`.venv\Scripts\python.exe -m src.formal_service --fetch`。

## 开发后台（v3.1.0）

双策略研究总览并列显示LightGBM核心卫星与通信/黄金趋势200的资金、收益、回撤、年度亏损和准入检查；同时显示正式数据审计与年度LightGBM训练折。

选ETF清单只使用周度信号日。LightGBM显示真实年度滚动预测的权益卫星排名，并单列国债、黄金底仓；排名还需经过持有期、缓冲与风险规则才能转成调仓建议。固定策略按三只ETF的市场资格、200日复权均线和替代条件显示，不生成模型评分。

周度调仓显示当前正式建议、模型持仓和输入账户试算。回测分析显示2016-09-12起的资金曲线、年度收益/回撤、十周历史持仓与完整成交记录。固定策略与LightGBM分别标明现金账本和复权全收益代理账户口径。

数据管道提供“更新行情并重建双策略”和“重建模型、回测和建议”，复用正式刷新任务与日志。两者均完整发布两条策略的同一运行版本，不调用旧训练或每日决策命令。浏览历史时绑定所见run_id，刷新后需重新查询以避免混用不同快照。
