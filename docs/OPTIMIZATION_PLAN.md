# 稳定性与性能优化计划

> 本文记录前一阶段的工程基线。当前v2采用252日年化、复利净值和版本化研究；最新结果以 [量化验收报告](QUANT_ACCEPTANCE.md) 为准，下面的238日页面记录和40项测试数仅保留作为阶段历史。

本轮目标：提高数据写入、Web 管道执行和结果查询的可靠性，降低重复查询与日志轮询开销。保留工作区已有的数据源、指数基准和训练退化保护修改。

## 实施步骤

- [x] 数据存储：将 DuckDB 删除与插入合并到事务中，失败回滚，并确保临时注册表释放。
- [x] 管道执行：补全异常、启动失败与后续步骤跳过状态；实时刷新子进程日志，按块读取日志尾部；训练指标原子写入并兼容非有限数值。
- [x] 结果查询：强化并发缓存及文件变化检测，缓存预测日期索引；校验日期与 TopK，处理空回测、非有限指标和空可交易池。
- [x] 前端配合：避免轮询重叠和重复提交，支持静默轮询与取消请求，展示跳过状态，年化天数从接口获取；ECharts 按需引入折线图组件。
- [x] 验证与交付：增加可离线运行的回归测试，运行 API 冒烟检查与前端构建，记录验证结果与使用命令。

## 验收标准

1. 插入失败后，原数据库记录仍存在，连接可以继续正常写入。
2. 管道异常后不再残留运行中状态，失败原因可查询，后续步骤标记为跳过；训练完成即保存指标。
3. 无效请求返回明确的 4xx；单日、空报告与非有限数值不会导致 JSON 序列化 500；空可交易池不回退为全池。
4. 未变化的预测文件不重复加载或构建日期索引，日志尾部读取不随完整历史日志占用内存。
5. 自动化验证仅使用临时数据库、临时文件和模拟任务，不触发真实行情抓取、重训或持仓更新。

### 使用命令与边界

```powershell
# 在已安装根目录依赖的项目虚拟环境中运行
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v

cd frontend
npm ci --no-audit --no-fund
npm run build
```

- 后端仍需单 worker；本轮解决进程内并发与失败状态，任务状态不跨服务重启恢复。
- 日期参数为 `YYYY-MM-DD`；TopK 范围为 1–50；日志 tail 范围为 1–10,000。缺失产物返回 404，正在改写或损坏的预测/报告返回 503（含 `Retry-After: 2`）。
- 空回测以 `days=0` 和空指标返回；NaN/Infinity 以 JSON null 表示，非有限预测打分不进入清单。
- 前端构建仍提示 Element Plus 主包和图表分块超过 500 kB，以及第三方 PURE 注释警告；构建和页面功能验证均通过。
- 未运行真实行情抓取或完整训练，因此这些改动不构成策略收益改善的验证。
