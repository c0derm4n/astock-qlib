# 两个"估值分位＋分批"策略的抽象

日期：2026-11-09。来源：用户在网络上看到的两个帖子截图（知乎 @CHLOE，2026-11 截图），非本项目的实验产物。

本文只做**策略抽象**：把帖子里的自然语言描述还原成可检验、可实现的规则族，并列出必须先补齐的定义。**本文没有跑任何回测，不产生新的历史绩效数字，也不改变任何生产指针或冻结协议。**

图中作者自报的数字（30.87%、87.50%、20.32%、20 个月）是**作者自述的历史回放结果**，不是本项目核验过的证据。

## 0. 一句话结论

两个帖子是同一个骨架的两个实例：**用指数估值分位决定"买多少份、什么时候全清"，用另一类资产承接空仓资金**。骨架可以抽象成一个三阈值、深度加权的仓位状态机（下称 **VBA：Valuation-Band Accumulation**），两个帖子分别是：

| | 策略 1（帖 A） | 策略 2（帖 B） |
|---|---|---|
| 交易标的 | 沪深300（全收益口径） | 创业板指 |
| 估值指标 | PE（市盈率） | PB（市净率） |
| 买入线 | 历史低点 PE 中位数 × 110% | 历史低点 PB 中位数 × ？（文中未给系数） |
| 深入线 | 图例有"深入线"，文中未给公式 | 同 |
| 清仓线 | PE=14.34（历史 85% 分位）；正文另说"PE 大于 14 可以分批清仓" | PB 历史 75% 分位 |
| 建仓节奏 | 分批（图上有"买+2/买+3/买+5/买+7"） | 同 |
| 二次确认 | 沪深300 全收益 × 二级债基 交叉点 | 无 |
| 空仓资产 | 二级债基 | 红利低波（股息率 > 5% 时买入） |
| 自报结果 | 平均持仓 20.2 个月，单笔含分红 +30.87%，"回撤可控制在 20% 以内" | 平均持仓 21.9 个月，单笔 +87.50%，最大回撤 20.32% |

## 1. 事实层：帖子里到底写了什么

### 1.1 帖 A（沪深300）

原文可摘出的明确表述：

1. 取"沪深300 几个历史低点当天"的 PE，求**中位数**；
2. **买入线 = 中位数 × 110%**；
3. "PE 大于 14 可以分批清仓"；
4. "拿 PE=14.34（历史 85% 分位）当作清仓线回测，平均每笔持仓 20.2 个月，含分红收益 30.87%"；
5. "再结合着沪深300 全收益 和二级债基交叉点分批建仓会更好。安全边际会很高，回撤可以控制在 20% 以内"；
6. 图例：`实际点位 / 买入线 / 深入线 / 清仓线 / 买 / 卖`；第一张图是"沪深300 历史低点 PE 中位数"在**指数点位**上的映射，第二张图是"沪深300 全收益"与"二级债基"两条曲线。
7. 图上"买"标记带份数后缀（买+2、买+3、买+4、买+5、买+7），"卖"标记为单点。

### 1.2 帖 B（创业板指）

1. "创业板指建议用 PB 估值"；
2. "拿历史 75% 分位 PB 作清仓线"；
3. "平均每笔持仓 21.9 个月，收益 87.50%，最大回撤 20.32%"；
4. "其他空仓时间，看着红利低波股息率 > 5% 就把钱丢进去就行了"；
5. 图例同上（含"深入线"）；标记同样带份数（买+7、买+2、卖）。

### 1.3 帖子内部的自相矛盾（必须由我们选定口径）

| 冲突 | 帖 A 的说法 1 | 帖 A 的说法 2 | 处理建议 |
|---|---|---|---|
| 清仓阈值 | "PE 大于 14 可以分批清仓" | "PE=14.34（历史 85% 分位）当清仓线" | 两者不能同时成立；建议**用分位（85%）作主参数**，14.34 视为该分位的当前映射值，避免写死绝对数 |
| 清仓方式 | "分批清仓" | 图上只有单个"卖"标记 | 建议抽象成参数 `exit_mode ∈ {一次性, 分批}`，默认一次性、分批作敏感性 |
| 买入线系数 | 帖 A 给了 110% | 帖 B 完全没给 | 帖 B 的买入线系数是**未知参数**，不能倒推后当成"作者原规则" |
| "深入线" | 图例有 | 正文没定义 | 只能当作"比买入线更低的一档加仓线"，具体倍数未知 |

## 2. 抽象：VBA 估值带累积框架

### 2.1 状态与变量

- `A`：单一宽基指数标的（可用 ETF 交易，如 510300 / 159915）。
- `V_t`：决策时点 `t` 的**当时可得**估值指标（`PE_TTM` 或 `PB`，MRQ/TTM 口径须固定）。
- `M_low`：历史低估样本的**中位数**——帖子的关键构造。样本 = "几个历史低点当天"的 `V`。
- 三条阈值（严格递减）：`S`（清仓线） > `L_buy`（买入线） > `L_deep`（深入线）。
- `U`：总份数上限（仓位的"份"单位，例如 10 份 = 满仓）。
- `u_t ∈ {0,1,…,U}`：当前已持份数；`c_t = 1 - u_t/U`：空仓资金比例。
- `g_t ∈ {0,1}`：二次确认门（帖 A 的"全收益 × 二级债基交叉点"；帖 B 无此层，恒为 1）。

### 2.2 阈值定义（把帖子公式化）

```
M_low  = median{ V(τ) : τ ∈ 历史低点集合 }
L_buy  = (1 + α) · M_low            # 帖 A：α = 10%
L_deep = (1 + β) · M_low            # 帖未定义；β < α，需标定
S      = Quantile(V_history, q)     # 帖 A：q = 85%；帖 B：q = 75%
```

关键点：`L_buy` 是**相对量**（跟随 `M_low` 漂移），`S` 是**分位量**（跟随历史分布漂移），所以图上四条带是随时间上移的曲线，而不是固定点位。这也解释了为什么帖 A 的图里"买入线"从 ~3,300 抬到 ~4,000。

### 2.3 仓位规则（深度加权阶梯）

```
d_t = clamp((L_buy - V_t) / (L_buy - L_deep), 0, 1)     # 低估深度
k_t = clip(ceil(k_min + (k_max - k_min) · d_t), 1, k_max)  # 本次加几份
```

| 条件 | 动作 |
|---|---|
| `V_t ≥ S` | 清仓：`u* = 0`（或分批减仓，`u* = max(u_t - k_out, 0)`） |
| `L_buy ≥ V_t > L_deep` | 加仓 `k_min` 份（帖图的"买+2"） |
| `V_t ≤ L_deep` | 加仓 `k_max` 份（帖图的"买+7"，越深越重） |
| `L_deep < V_t < L_buy` 且 `g_t = 0` | 不买（门控未开） |
| 其余（`L_buy < V_t < S`） | 持有不动 |

资金约束：`u* = min(u* , U)`，且单次加仓不得使空仓资金低于流动性下限。

### 2.4 二次确认层（只属于帖 A）

抽象为"相对估值门"，不绑定具体实现：

```
R_t = TR_t / B_t                        # 权益全收益指数 / 债券类净值
g_t = 1{ R_t ≤ Quantile(R_history, p_R) }   # 跌破历史低分位才允许加仓
```

帖子里的"交叉点"其实就是 `R_t` 触及低位（权益相对债券跌到极端）的时点。它把纯估值信号（PE 低）与相对强弱信号（股比债便宜）叠成 AND 门，用来压住"PE 低但还能更低"的左侧风险。

### 2.5 空仓资产（现金替代）

空仓期不是纯现金，而是"防守资产 + 择时门槛"：

- 帖 A：二级债基（无门槛，常驻）。
- 帖 B：红利低波，**仅当股息率 > 5%** 才买入，否则现金。

抽象成 `idle_asset` 及其门槛 `y_th`（股息率阈值）。这一层决定了账户的"底仓收益"，也是两个帖子声称回撤小的重要原因。

### 2.6 状态机

```
        V≥S                        V≤L_buy & g
[空仓] ────────► [持有] ◄────────────────────── [建仓中]
   ▲               │  ▲                              │
   │               │  └──── V≤L_deep（继续加份）─────┘
   └───────────────┘ V≥S（清仓）
```

本质：**左侧分批买入 + 估值到顶一次性离场 + 空仓期换防守资产**。它是一个单资产、低频、均值回归型的择时叠加层，不是横截面选股/选 ETF 的轮动策略。

## 4. 自报数字的量化含义（算术推演，非回测）

把"平均每笔 +30.87%、持仓 20.2 个月"折算成**在场期间**的年化：

- 帖 A：`(1.3087)^(12/20.2) - 1 ≈ 17.3%/年`（在场时）
- 帖 B：`(1.8750)^(12/21.9) - 1 ≈ 41.1%/年`（在场时）

再看资金利用率（空仓期只有防守资产收益，这里保守按 0 计）对**账户** CAGR 的影响：

| 在场时间占比 | 帖 A 账户 CAGR | 帖 B 账户 CAGR |
|---|---|---|
| 100% | 17.3% | 41.1% |
| 80% | 13.6% | 31.7% |
| 60% | 10.1% | 23.0% |
| 50% | 8.3% | 18.8% |
| 40% | 6.6% | 14.8% |

结论：

1. **单笔收益 ≠ 年化收益**。帖子给的是"每笔"，不是账户 CAGR，也不是年度收益；两者之间还差一个"在场比例"。
2. 帖 A 在 60%~70% 在场率下就落到 10%~12%，**很可能达不到本项目 13.50% 的 CAGR 门槛**；帖 B 的 41% 在场年化几乎完全来自创业板 2018-10 至 2021-07 那一轮（指数 1,200 → 3,500），是**单一牛市样本**，不能外推。
3. "回撤控制在 20% 以内"是**账户口径**的说法，但帖子没交代：是否含空仓期的净值、是否按每日收盘、是否含分红再投资、是否在 2015 年那种 -45% 的路径里也成立。这些口径不补齐，20% 和 20.32% 都不可复核。

### 4.1 必须点明的偏差

- **后视偏差**：`α = 110%`、`q = 85%`、`q = 75%`、`PE = 14.34` 都是在看完全部历史之后选出来的"刚好让曲线好看"的数。这类参数在样本内几乎必然有效。
- **低点样本偏差**：`M_low` 用"历史低点当天"的 PE 求中位数，前提是**已经知道哪些天是低点**。实盘时点无法知道"今天是不是历史低点"，只能换成"截至今日的历史分位"，这是两套规则。
- **生存偏差**：只在沪深300 / 创业板指这两个"活到今天且长期上行"的指数上演示，换成中证500、恒生、日经，同样的参数不成立。
- **交易次数极少**：20 个月/笔意味着十年只有个位数决策，**统计上无法做显著性检验**，任何"最优参数"都不可靠。

## 5. 缺口清单（补齐后才可回测）

按重要性排序，括号内是建议默认值：

1. `M_low` 的样本定义（建议：滚动 10 年内 `V` 的历史分位 ≤ 20% 区间的日均值，或每年最低点的中位数——两者必须二选一并冻结）。
2. 买入线系数 `α`（A 用 10%；B 无，建议同 10% 作起点）。
3. 深入线系数 `β`（建议 `L_deep = M_low`，即 β=0）。
4. 总份数 `U` 与单份金额（建议 U=10，等额）。
5. 加仓冷却与最小间隔（建议：同一估值档位 20 个交易日内不重复加仓，避免"跌一点就加一份"的隐式高频）。
6. 清仓方式（一次性 vs 分批）与分批档数。
7. 决策频率（**本项目必须周频**：周一收盘评估、下一交易日开盘执行）。
8. 估值口径：PE 用 TTM 还是静态、PB 用 MRQ；**必须用当时可得的发布值**，不能用最新成分回溯。
9. 全收益指数与分红处理口径。
10. 二级债基 / 红利低波的代理标的与"股息率 > 5%"的数据源。
11. 费率、滑点、最小变动单位。
12. 空仓期收益是否计入账户净值。

## 6. 与本项目约束的对齐

### 6.1 合规（硬约束）

- 标的必须非美股：沪深300ETF（510300）、创业板ETF（159915）均在 ETF 池内，**合规**。
- 帖 A 的"二级债基"、帖 B 的"红利低波"**不在池内**：池内可用替代是十年国债 ETF（511260）和红利 ETF（510880，但缺股息率数据）。若要用原帖口径，需新增标的并单独登记，不能直接塞进现有池。
- 不得引入标普/纳指相关标的做替代或对照交易（见 [投资偏好](INVESTMENT_PREFERENCES.md)）。

### 6.2 数据缺口（当前仓库没有）

`data/market.duckdb` 只有 ETF 日线、复权因子、净值等表，**`index_daily` 为空，没有任何 PE/PB/股息率序列**。要落地这两个策略，第一步是新增估值数据源并登记（指数 PE/PB 日频、全收益指数、债券类净值、红利低波股息率），并给出可得性时点审计。在此之前，**这两个策略在本项目内不可回测**。

### 6.3 与用户目标的冲突

- 用户目标：CAGR ≥ 13.50%、最差完整年 ≥ −5%、最大回撤 ≤ 40%，且风险优先于收益。
- 本框架的结构性优势在**回撤**（大部分时间低仓/空仓），结构性劣势在**CAGR**（现金拖累 + 十年仅个位数决策）。
- 因此合理定位是**风险叠加层 / 卫星择时**，而不是替代 `trend200_vol15` 的主策略。若要用，应作为"权益仓位开关"叠加在现有固定配置上，并单独验证叠加后的三项指标。

### 6.4 频率口径

用户要求周一首个交易日收盘评估、下一交易日开盘执行、触发才调仓。帖子是日频估值 + 按月级别的操作，两者不同。**日频估值阈值转周频采样后必须重新验证**，不能把日频结果当周频结果（这是本项目已明确的口径纪律）。

## 7. 可实现的接口（伪代码）

```python
@dataclass
class VBAParams:
    metric: str            # "pe_ttm" | "pb_mrq"
    alpha: float           # 买入线系数, 0.10
    beta: float            # 深入线系数, 0.00
    exit_quantile: float   # 0.85 | 0.75
    exit_mode: str         # "all_at_once" | "staged"
    total_units: int       # 10
    k_min: int             # 2
    k_max: int             # 7
    cooldown_days: int     # 20
    gate: str | None       # None | "equity_bond_ratio"
    idle_asset: str        # "bond_etf" | "dividend_lowvol"
    idle_yield_threshold: float | None   # 0.05

def target_position(v_t, hist_v, state, p: VBAParams) -> int:
    m_low = median_low_samples(hist_v)          # 见缺口 1
    l_buy, l_deep = (1+p.alpha)*m_low, (1+p.beta)*m_low
    s = quantile(hist_v, p.exit_quantile)
    if v_t >= s:
        return 0 if p.exit_mode == "all_at_once" else max(state.units - 5, 0)
    if v_t > l_buy or state.cooldown > 0:
        return state.units
    if p.gate and not gate_open(state):          # 帖 A 的二次确认
        return state.units
    d = clamp((l_buy - v_t) / (l_buy - l_deep), 0, 1)
    k = clip(ceil(p.k_min + (p.k_max - p.k_min) * d), 1, p.k_max)
    return min(state.units + k, p.total_units)
```

周频落地：`evaluate(周一收盘) -> target_units`，`execute(周二开盘)`，用现有 `weekly_first_session_close_next_open` 口径。

## 8. 建议的验证顺序（不切换生产）

1. **数据准入**：PE/PB/全收益/股息率序列入库 + 时点可得性审计。
2. **规则冻结**：先把第 5 节 12 项缺口填死并写入协议 JSON，再跑第一次回测（避免事后改参数）。
3. **周频复现**：只在周频采样下验证，分别报 CAGR / 最差完整年 / 每日最大回撤，与帖子自述的"每笔收益"分开披露。
4. **参数敏感性**：`α ∈ {1.00, 1.05, 1.10, 1.20}`、`q ∈ {0.70, 0.75, 0.80, 0.85, 0.90}`、`U` 与 `k` 阶梯。若相邻参数结果跳变，判定为过拟合。
5. **与现有候选叠加**：把"估值门"叠加到 `trend200_vol15` 的权益敞口上，比较三项联合指标是否改善。
6. **前瞻观察**：≥126 个交易日，再谈准入。
